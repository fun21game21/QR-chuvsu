# QR-CHUVSU v2

Система автоматизированной отметки студентов по QR-коду. Преподаватель создаёт занятие, показывает QR-код, получает журнал и скачивает Excel. Студент открывает ссылку с телефона, вводит ФИО и группу и разрешает геолокацию. Отдельное приложение не нужно.

Это переработанная версия учебного проекта QR-CHUVSU, представленного в материалах защиты Максима Колсанова и Дмитрия Стенейкина. Концепция сохранена, backend и хранение данных реализованы заново на FastAPI и PostgreSQL. Исходные презентация и материалы защиты в репозиторий не включены.

## Quick Start

1. Установите и **запустите** [Docker Desktop](https://www.docker.com/products/docker-desktop/). На Linux можно использовать Docker Engine с Compose plugin.
2. Установите Git. Скопируйте URL этого репозитория через зелёную кнопку **Code → HTTPS** на GitHub.
3. Откройте терминал и выполните, заменив `<OWNER>` владельцем опубликованного репозитория:

   ```bash
   git clone https://github.com/<OWNER>/qr-chuvsu-v2.git
   cd qr-chuvsu-v2
   docker compose up --build
   ```

4. Дождитесь запуска контейнеров. Откройте [http://localhost](http://localhost).
5. Создайте QR-сессию, укажите группу, выберите корпус ЧГУ и задайте радиус. Откройте форму студента, заполните её, разрешите геолокацию, проверьте журнал и скачайте Excel.

Для локальной демонстрации файл `.env` не нужен. База и таблицы создаются автоматически. На компьютере не требуется устанавливать Python, PostgreSQL или Node.js. Первая сборка требует интернета для загрузки образов и библиотек.

**Проверка с телефоном:** QR по умолчанию содержит `http://localhost`. На телефоне этот адрес указывает на сам телефон. Чтобы открыть QR с другого устройства и получить геолокацию, настройте доступный телефону HTTPS-домен и `PUBLIC_BASE_URL` по [инструкции HTTPS](docs/HTTPS.md). Внешний сервер и сертификат не создаются автоматически.

Без Git: выберите **Code → Download ZIP**, распакуйте архив, откройте терминал в папке с `docker-compose.yml` и выполните ту же команду запуска.

## Возможности

- Создание занятия: название, группа, преподаватель, корпус из списка, длительность и радиус; координаты корпуса подставляет сервер.
- 21 обозначение учебных корпусов ЧГУ в Чебоксарах: [координаты, источники и особенности точек](docs/CAMPUSES.md).
- QR-код в PNG и шестизначный код, включая ведущие нули. Вход по коду с главной страницы.
- Мобильная форма: ФИО, группа и кнопка отметки.
- Проверка активности и срока сессии, группы, повторного ФИО и группы.
- UUID устройства в подписанной HttpOnly cookie; fingerprint из user-agent, языка, часового пояса и размеров экрана.
- HTML5 Geolocation API, расстояние по Haversine в метрах. Отсутствие координат и выход за радиус отклоняются.
- Сохранение успешных отметок и отклонённых попыток с причиной.
- Ограничение частоты запросов по IP, совместимое с несколькими студентами в одной Wi-Fi-сети.
- Панель преподавателя: QR, код, количество студентов, журнал по группам, список отказов.
- Ручное добавление преподавателем при проблемах с телефоном или геолокацией.
- Досрочное закрытие, возврат к активным занятиям с главной, расписание звонков.
- Excel: листы «Журнал» и «Отклонённые попытки», сортировка по группам; ФИО, группа, дата, время, статус и причина.
- Автообновление панели каждые 15 секунд, приостановленное на время ручного ввода.

Регистрации, логина, пароля и личного кабинета **нет**. Право управления сессией связано с подписанной cookie браузера, создавшего занятие. Ссылка студента не даёт доступа к журналу или Excel. При удалении cookie преподаватель теряет доступ к созданным сессиям; переноса доступа между устройствами здесь нет. Не используйте общий профиль браузера для разных преподавателей.

## Архитектура

```text
Браузер: HTML / CSS / JavaScript
               |
         Nginx :80 / :443
               |
     FastAPI + Jinja2 :8000
               |
```

### Стек

Python 3.12 в Docker, FastAPI, asyncpg, Pydantic 2, Jinja2, qrcode, openpyxl, PostgreSQL 16, Nginx, Docker Compose. Frontend без сборщика: HTML, CSS, JavaScript. React, Vue, Angular, SQLAlchemy и другие ORM не используются. Проверенная среда и результаты приведены в [отчёте](docs/TEST_REPORT.md).

### Данные и конкурентные запросы

`sessions` и `attendance` содержат все поля исходного задания. Дополнительно хранятся преподаватель, место, хеш владельца, нормализованные ключи имени/группы, причина отказа, расстояние и введённый код. `qr_path` указывает на защищённый endpoint, который генерирует PNG по запросу: файловое хранилище изображений не требуется.

Служебные таблицы: `schema_migrations` и `ip_rate_limits`. Миграции из `postgres/*.sql` применяются один раз под транзакционной блокировкой. Уже применённые миграции не редактируют: изменения схемы добавляют новым пронумерованным SQL-файлом.

Отметка блокирует строку сессии через `SELECT ... FOR UPDATE`. Проверки и запись выполняются в одной транзакции. Частичные уникальные индексы дополнительно предотвращают две успешные отметки одного студента или устройства. Все значения передаются параметрами SQL. Даты хранятся в `timestamptz`, отображаются в настроенном часовом поясе.

Статусы: `accepted` — самостоятельная отметка; `manual` — добавление преподавателем; `rejected` — отказ. Отказ не занимает устройство. Для неизвестного шестизначного кода попытка сохраняется с `session_id=NULL`. Ошибки формата JSON/полей, CSRF и запросы, отсечённые Nginx до приложения, не являются записями журнала посещаемости.

Одна сессия предназначена для одной указанной группы; сравнение не зависит от регистра и повторных пробелов. Преподаватель может вручную внести присутствующего из другой группы. Так журнал и Excel сохраняют группировку без отдельного справочника студентов.

## Запуск и настройка .env

Дополнительный режим запуска в фоне с ожиданием готовности:

```bash
docker compose up --build -d --wait
docker compose ps
docker compose logs --tail=100 backend nginx postgres
```

Для изменения настроек скопируйте `.env.example` в `.env` (PowerShell также поддерживает `cp`):

```bash
cp .env.example .env
```

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PUBLIC_BASE_URL` | `http://localhost` | Внешний адрес без пути; используется в QR и проверке Origin |
| `HTTP_PORT` | `80` | Порт HTTP на компьютере |
| `POSTGRES_PASSWORD` | `qr_local_demo` | Пароль учебной БД; перед внешним запуском замените |
| `APP_SECRET` | пусто | Пусто: секрет генерируется и сохраняется в Docker-томе. Явный секрет: минимум 32 символа |
| `COOKIE_SECURE` | `false` | Обязательно `true` при HTTPS |
| `TIMEZONE` | `Europe/Moscow` | Часовой пояс журнала и Excel |
| `IP_RATE_LIMIT` | `120` | Создания, входы по коду и попытки отметок за 60 секунд с одного IP |

Для простоты используйте длинный пароль БД из букв и цифр: Compose вставляет его в `DATABASE_URL`. Если нужен пароль со специальными символами, настройте отдельно корректно URL-кодированный `DATABASE_URL` в Compose; значение `POSTGRES_PASSWORD` у PostgreSQL остаётся исходным. Изменение переменной пароля не меняет пароль уже инициализированной БД: используйте PostgreSQL `ALTER ROLE` либо создайте новую учебную базу.

При занятом порте 80 задайте `HTTP_PORT=8080` и `PUBLIC_BASE_URL=http://localhost:8080`. После изменения `.env` выполните `docker compose up -d --build`. Внешний URL в браузере должен совпадать с `PUBLIC_BASE_URL`, включая порт. `localhost` и `127.0.0.1` — разные адреса для cookie и Origin.

Внутренние настройки для запуска backend вне Compose: `DATABASE_URL`, `SECRET_FILE`, `SCHEDULE_FILE`, `RATE_WINDOW_SECONDS`. Они описаны в `backend/app/config.py`. Основной проверяемый способ запуска — Docker.

Расписание в `backend/app/schedule.json` явно помечено демонстрационным: материалы защиты не содержат полного подтверждённого расписания. Перед использованием замените часы на расписание своего корпуса и пересоберите backend.

### Остановка и сохранность

```bash
docker compose down
```

Тома `postgres_data` (журнал) и `app_data` (секрет cookie) сохраняются. Повторный запуск не удаляет записи. Смена/потеря секрета делает старые cookie недействительными.

**Только для полного сброса учебных данных** команда `docker compose --profile test down -v` удаляет тома вместе с журналом и секретом. Не используйте её для обычной остановки.

Пример резервной копии (bash/zsh):

```bash
docker compose exec -T postgres pg_dump -U qr -d qr_chuvsu > backup.sql
```

Копию держите вне публичного репозитория. Секрет `app_data` необходимо сохранять отдельно для восстановления доступа преподавателей.

## Использование и ручная проверка

1. Откройте главную страницу и нажмите «Создать QR-сессию». Введите занятие, группу и преподавателя, выберите корпус ЧГУ.
2. Координаты выбранного корпуса определятся автоматически. Задайте радиус, например 150 м, и длительность 30 минут.
3. Убедитесь, что панель показывает QR и шесть цифр. Вернитесь на главную и откройте занятие через «Вернуться к активной сессии».
4. Откройте ссылку «Открыть форму студента» для проверки на компьютере. Для телефона сначала выполните [HTTPS-настройку](docs/HTTPS.md), затем сканируйте QR. Альтернатива — ввод кода на главной.
5. Введите тестовое ФИО и группу, разрешите геолокацию и нажмите «Отметиться». Находясь в радиусе выбранного корпуса, вы получите «Отметка подтверждена». В панели появится запись. При проверке из дома ожидается отказ по расстоянию; для проверки журнала используйте ручное добавление или автоматические тесты.
6. Перезагрузите форму и отправьте те же данные. Ожидается «Вы уже отметились». В журнале остаётся одна успешная запись и появляется отказ.
7. Создайте отдельную сессию на 1 минуту, дождитесь завершения и отправьте заранее открытую форму. Ожидается «Сессия недействительна».
8. Для новой сессии запретите геолокацию в браузере. Отправьте форму: появится отказ и причина в панели. Для проверки выхода из зоны выберите корпус, заведомо удалённый от вашего местоположения и разрешите текущую геолокацию.
9. В панели раскройте «Добавить студента вручную», введите другое ФИО. Запись должна иметь способ «Вручную».
10. Нажмите «Скачать Excel», откройте `.xlsx` в Excel или LibreOffice. Проверьте оба листа, ФИО, группы, даты, время и статусы.
11. Нажмите «Закрыть сессию» и подтвердите. Новые отметки отклоняются, журнал и Excel остаются доступны по адресу панели.

Геолокация внутри зданий может быть неточной. Проверки — мягкая защита учебного проекта: браузерные данные и координаты можно подменить, cookie удалить, а fingerprint одинаковых моделей телефонов может совпасть. Сайт не получает IMEI/MAC и не доказывает физическое присутствие. Для спорных случаев предусмотрено ручное добавление преподавателем.

## API

Интерактивное описание: [Swagger UI](http://localhost/docs). Схема: `/openapi.json`. API используется тем же браузером, что и HTML. Для изменяющих запросов нужны cookie `qr_device` и заголовок `X-CSRF-Token` из `<meta name="csrf-token">` страницы. В Swagger добавьте этот заголовок самостоятельно либо используйте пример ниже.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/health` | Готовность приложения и PostgreSQL |
| POST | `/api/sessions` | Создание сессии |
| POST | `/api/sessions/resolve` | Вход по `{"code":"123456"}` |
| GET | `/api/sessions/{id}/qr.png` | QR, только создатель |
| POST | `/api/attendance/{code}` | Отметка студента |
| GET | `/api/sessions/{id}/attendance` | Журнал, только создатель |
| POST | `/api/sessions/{id}/manual` | Ручное добавление: ФИО, группа |
| POST | `/api/sessions/{id}/close` | Закрытие |
| GET | `/api/sessions/{id}/export` | Excel, только создатель |

Пример JSON создания:

```json
{
  "title": "Базы данных",
  "group_name": "ИВТ-21",
  "teacher_name": "Иванов Иван Иванович",
  "campus_id": "chuvsu-g",
  "duration_minutes": 30,
  "radius": 150
}
```

Идентификаторы и источники координат: [справочник корпусов](docs/CAMPUSES.md). API создания принимает только `campus_id`; передача `latitude`, `longitude` или `location_name` отклоняется. Название и координаты сохраняются в сессии и не меняются при последующих обновлениях справочника. Существующие занятия сохраняют исходную геозону.

Пример отметки:

```json
{
  "student_name": "Петров Пётр Петрович",
  "group_name": "ИВТ-21",
  "latitude": 56.1457245,
  "longitude": 47.2243805,
  "fingerprint": {
    "user_agent": "ExampleBrowser/1.0",
    "language": "ru-RU",
    "timezone": "Europe/Moscow",
    "screen_width": 390,
    "screen_height": 844
  }
}
```

Пример вызова из DevTools на главной странице, для тестовой сессии:

```javascript
const csrf = document.querySelector('meta[name="csrf-token"]').content;
const response = await fetch('/api/sessions/resolve', {
  method: 'POST',
  headers: {'Content-Type': 'application/json', 'X-CSRF-Token': csrf},
  body: JSON.stringify({code: '123456'})
});
console.log(await response.json());
```

Ответ отметки: `status`, `reason`, `message`. HTTP: `200` успех; `201` сессия создана; `403` CSRF; `404` панель недоступна этому браузеру; `409` повтор/устройство/fingerprint; `410` недействительная сессия; `422` некорректные поля, группа или геолокация; `429` ограничение частоты. Пример: `{"status":"rejected","reason":"duplicate","message":"Вы уже отметились"}`.

## Автоматическая проверка

```bash
docker compose up --build -d --wait
docker compose --profile test run --build --rm tests
docker compose --profile test run --rm tests ruff check app tests
```

Тесты создают отдельный контейнер `postgres-test` с БД `qr_chuvsu_test` в tmpfs. Интеграционные тесты отказываются работать с другим именем БД. Они очищают только эту тестовую БД. HTTP smoke-тест дополнительно создаёт одну демонстрационную сессию через работающий Nginx в основной БД и закрывает её после проверки.

Проверяются обязательные сценарии, конкурентные дубли, доступ к чужой панели, CSRF, IP-лимит, ручные отметки, SQL-инъекции как обычный текст, HTML-экранирование и отсутствие формул из пользовательского текста в Excel. GitHub Actions выполняет те же команды при push и pull request. [Фактический отчёт проверки](docs/TEST_REPORT.md).

## Эксплуатация и устранение проблем

- Docker daemon недоступен: запустите Docker Desktop и дождитесь готовности.
- Порт 80 занят: измените `HTTP_PORT` и `PUBLIC_BASE_URL` вместе.
- Подсеть `172.30.92.0/24` уже занята: замените subnet, ip_range, статический адрес Nginx и `FORWARDED_ALLOW_IPS` согласованно; пересоздайте сеть через `docker compose down`, затем запустите снова. Тома не удаляйте.
- На телефоне не работает QR: убедитесь, что URL доступен телефону и содержит HTTPS-домен, а не localhost.
- Геолокация запрещена: разрешите её в настройках сайта и ОС либо используйте ручную отметку.
- Панель показывает 404: откройте её в браузере, создавшем занятие. Cookie нельзя восстановить из публичного кода.
- Ошибка «Недопустимый источник запроса»: адрес страницы должен совпадать с `PUBLIC_BASE_URL`.
- После изменения IP-лимита перезапустите backend. Несколько студентов за одним IP допустимы; лимит должен учитывать размер потока.

Данные хранятся до удаления администратором. Для выбранной установки определите срок хранения и контакт ответственного, обновите `/privacy`. Пример удаления записей старше 90 дней (не запускается автоматически):

```bash
docker compose exec postgres psql -U qr -d qr_chuvsu -c "DELETE FROM sessions WHERE expires_at < now() - interval '90 days'; DELETE FROM attendance WHERE session_id IS NULL AND created_at < now() - interval '90 days';"
```

Связанные отметки удаляются через `ON DELETE CASCADE`. Не публикуйте реальные журналы, `.env`, сертификаты и резервные копии.

Создайте пустой репозиторий `qr-chuvsu-v2` в своём аккаунте. В папке проекта выполните:

```bash
git init
git add .
git commit -m "Initial QR-CHUVSU v2 implementation"
git branch -M main
git remote add origin https://github.com/<OWNER>/qr-chuvsu-v2.git
git push -u origin main
```

Если репозиторий или remote уже существуют, используйте их вместо повторной инициализации. Замените `<OWNER>` в инструкции Quick Start на реального владельца. Проект подготовлен к публикации; автоматического создания репозитория и отправки исходников во внешний аккаунт нет.
