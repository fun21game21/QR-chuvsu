# Отчёт проверки QR-CHUVSU v2

Дата обновлённой проверки: 19 сентября 2026 года. Проверка выполнена локально на macOS ARM64 с Docker Desktop. Runtime приложения — Linux-контейнер Python 3.12.14, PostgreSQL 16, Nginx 1.28. Docker Engine 29.7.2, Compose v5.4.0.

## Результат

**64 автоматических теста прошли; ошибок тестов нет.** Приложение запущено на `http://localhost`. Backend, PostgreSQL и Nginx имеют статус `healthy`. SQL-миграции `001_initial.sql` и `002_session_campus.sql` применены. Проверка `nginx -t` успешна. В журнале окончательного запуска FastAPI: `Application startup complete`.

### Воспроизводимые команды

```bash
docker compose up --build -d --wait
docker compose --profile test run --build --rm tests
docker compose --profile test run --rm tests ruff check app tests
docker compose exec nginx nginx -t
docker compose ps
```

Проверка чистой установки проведена с новыми томами. На первом запуске обнаружен конфликт динамического адреса backend со статическим адресом Nginx. Исправление: динамический IP-диапазон выделен отдельно от адреса Nginx. После этого контейнеры и созданные для проверки пустые тома были удалены, чистый запуск повторён успешно. Дополнительно проверена пересборка с сохранённой базой и секретом.

## Обновление выбора корпуса

Добавлены 29 проверок: создание сессии и успешная отметка для каждого из 21 корпусов; запрет неизвестного корпуса и подмены координат/места; отказ возле другого корпуса с записью расстояния; состав формы; работа прежних сессий без `campus_id`.

Результат последнего прогона: **64 passed, 1 warning in 2.12s**. Тестовая PostgreSQL пересоздана в tmpfs: обе миграции выполнены с нуля. Основная база сохранена. Smoke-тест прошёл через текущий Nginx и обновлённый backend, включая создание QR, отметку, дубль и открытие Excel библиотекой openpyxl.

Сборка runtime через `docker compose up --build -d --wait` успешна. Две попытки пересобрать тестовый образ остановились на сетевом тайм-ауте PyPI. Поэтому итоговый прогон использовал ранее собранный образ с установленными тестовыми зависимостями и текущие исходники/миграции через read-only mounts:

```bash
docker compose --profile test run --rm \
  -v "$PWD/backend/app:/srv/backend/app:ro" \
  -v "$PWD/backend/tests:/srv/backend/tests:ro" \
  -v "$PWD/postgres:/srv/postgres:ro" tests
```

Линтер `ruff check app tests` также проверил текущие исходники. Найденная при пересборке ошибка 502 устранена: Nginx обновляет адрес backend через Docker DNS (`resolver`, upstream `resolve`). Изменены HTTP-конфигурация и HTTPS-пример. [Документация Nginx](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#server).

В браузере проверены 21 пункт выпадающего списка, отсутствие ручного ввода координат и старого слогана, подпись «Доработан Максимкой», создание занятия в корпусе Е, правильный адрес в панели и закрытие тестовой сессии. Ссылки на источники и ограничения точек — в [справочнике](CAMPUSES.md).

## Проверка браузером

В браузере вручную проверены главная страница, создание демонстрационного занятия, появление QR и кода, ручное добавление и отображение студента в журнале. Мобильная форма проверена при viewport 390×844: `scrollWidth` равен 390, горизонтальной прокрутки нет.

При недоступной геолокации форма показала «Попытка отклонена: геолокация недоступна». Панель преподавателя отобразила ту же причину и увеличила счётчик отказов. В консоли этой проверки ошибок JavaScript не было.

## Границы проверки

- Успешная отметка проверена автоматическими запросами с тестовыми координатами, а не физическим телефоном в аудитории. Реальную точность GPS и сканирование камерой нужно проверить на месте после настройки HTTPS.
- Файл Excel успешно открыт и проверен библиотекой openpyxl. Дополнительная проверка через интерфейс Microsoft Excel была прервана пользователем; открытие в GUI не заявляется завершённым.
- Внешний HTTPS-домен, DNS и сертификат не настраивались по указанию заказчика. Подготовлены инструкция и необязательная конфигурация; публичное TLS-развёртывание не заявляется проверенным.
- Pytest выводит одно предупреждение DeprecationWarning из Starlette TestClient о старом псевдониме AnyIO BlockingPortal. Это предупреждение стороннего тестового инструмента, не ошибка приложения; все 64 теста завершаются успешно.
- После публикации выполнен [успешный запуск GitHub Actions](https://github.com/fun21game21/QR-chuvsu/actions/runs/35459604514): чистая сборка Docker, PostgreSQL, 64 теста и линтер. См. раздел ниже.
